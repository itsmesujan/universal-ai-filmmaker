# Changelog

All notable changes to this skill are documented here. Versioning rules:
[docs/versioning.md](docs/versioning.md).

## [1.1.0] - 2026-09-26

### Added

- **Routing and gates**: production-state detection, request classification, bounded
  clarification (three questions), and explicit pass conditions per stage
  (`references/intent-routing.md`).
- **Craft references (13 new)**: `story-and-script.md`, `bibles.md`, `shot-grammar.md`,
  `lighting-color.md`, `performance-direction.md`, `action-choreography.md`, `formats.md`,
  `prompt-compilation.md`, `risk-cost.md`, `reproducibility.md`, `multi-agent.md`,
  `evaluation.md`, `intent-routing.md`.
- **Deterministic tooling** (`scripts/`, Python 3.9+, standard library only):
  `uaf_lib.py`, `validate.py`, `prompt_compile.py`, `shot_budget.py`,
  `continuity_check.py`, `new_project.py`, `manifest.py`, `lint_skill.py`, `run_evals.py`.
- **Machine evals and human rubrics** (`evals/`): 6 cases with fixtures, plus rubrics for
  shot design, prompt quality, and QC discipline.
- **Schemas**: `beats.schema.json`, `continuity.schema.json`, `qc.schema.json`; enums,
  patterns, and minimums added to the existing project/shot/adapter schemas (with escape
  values, so 1.0 files stay valid).
- **Templates**: `story.md`, `script.md`, `scene.md`, `beats.json`, `continuity-ledger.json`,
  `storyboard.md`, `audio-plan.md`, `edit-plan.md`, `qc-report.json`, `runs.jsonl`,
  `project-readme.md`; richer `shot.md`, `character.md`, `location.md`, `style.md`,
  `qc-report.md`, `model-export.md`, `project.json`.
- **Examples**: `examples/mini-project/` (complete four-shot scene with ledger, beats, and
  manifest), `examples/model-adapter.example.json`.
- **Documentation**: 20-page `docs/` set — getting started, architecture, workflow, data
  model, shot spec, prompting, continuity, quality control, model adapters, multi-agent,
  CLI, evals, reproducibility, formats, versioning, security and rights, troubleshooting,
  FAQ, glossary.
- **CI**: lint, manifest freshness, schema/semantic validation, and evals run on push and
  pull request.

### Changed

- `SKILL.md` restructured around ten laws, routing, gates, canonical ids, a self-eval
  quality bar, prompt compilation, risk budgeting, reproducibility, and a failure protocol.
- Every 1.0 reference expanded with priorities, token defaults, failure modes, and fixes.
- `examples/shot-spec.example.json` is now an array, matching `shots.schema.json` (which has
  always required an array).
- Adapters gained `adapter_version`, `model_type`, `docs_url`, `degraded_mode`, and a
  `placeholder` marker; unverified capabilities must be the string `"unknown"`.
- `MANIFEST.json` is now generated by `scripts/manifest.py` and no longer lists itself
  (the 1.0 self-hash was stale: it recorded 3683 bytes for a 5267-byte file).
- Scorecard added to QC: pass at average ≥ 4.0 with no item below 3.

### Fixed

- Risk scoring now matches string *values* only; previously it also matched JSON keys, so
  `screen_direction` counted as a "text" risk in every shot.
- Cross-file semantic validation is now scoped per project directory instead of leaking
  between examples.
- The linter's repo-path check only inspects directory-qualified references, so upstream
  project artifacts are no longer mistaken for repository paths.
- `MANIFEST.json` hashes LF-normalised bytes and a `.gitattributes` enforces `eol=lf`, so
  `manifest.py --check` gives the same answer on Windows and Linux checkouts.

### Compatibility

- 1.0 project, shot, and adapter files remain valid: new fields are optional and new enums
  include escape values.
- Migration is optional and documented in [docs/versioning.md](docs/versioning.md).

## [1.0.0] - 2026-09-26

### Added

- Universal agent-first filmmaking workflow.
- Provider-neutral creative and cinematic planning layers.
- Canonical `SHOT_SPEC`.
- Character, location, style, and continuity guidance.
- Anime and cinematic production modes.
- Audio and editing planning.
- QC and repair workflow.
- Model adapter contract and templates.
- Project and shot JSON Schemas.
- Reusable templates and example shot.
- GitHub-ready documentation and validation workflow.
